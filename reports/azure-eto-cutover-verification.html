Verification results

  • 72 real database checks passed: INSERT, SELECT, UPDATE and DELETE on each of the 18 Azure tables. The verification transaction was rolled back; no test rows were retained.
  • 320 API tests passed: 319 passed in the full run; the remaining concurrency test passed after correcting its schema-qualified test isolation. Its temporary settings changes were restored and compared with the original data.
  • Workspace TypeScript checks passed. Route SQL, background jobs, and schema declarations were inspected for legacy database references.
  • Signed-in browser checks passed: draft creation, reload persistence, details edits and audit, comment posting, attachment upload/preview/download/deletion, ART assignment, due dates, Engineering and Production completion, ART Final quote, request-specific price calculation, list/search, dashboard and logout.
  • No server 5xx responses were found in the exercised browser journey. Disposable users, sessions, requests and related rows were removed and cleanup verified.
  • No wrong-schema foreign-key references: all app foreign keys point to crm tables.

Connection and safety controls

  • All runtime reads and writes, authentication sessions and background jobs use the writable Azure application pool. There is no local database fallback.
  • Startup verifies the required database, tables and CRUD permissions before serving requests.
  • The separate health-check connection remains read-only. Both pools handle idle connection errors.
  • Original local tables remain untouched as a backup. Unrelated CRM tables were not modified.
  • Migration is transactional and refuses existing destination tables; it is not an implicit merge tool.
  • Automatic post-merge remote schema pushes were removed. Schema tooling is restricted to the owned ETO tables.

Existing UI capabilities were retained. Comment deletion and request deletion are not existing UI/API actions; no new deletion controls were added. Their database delete operations were checked in the rollback-only table tests. Email delivery was not tested because email is disabled in this workspace.

Published release

This cutover is implemented and verified in the running workspace. It has not been published automatically, and records that exist only in the older published application's database have not been migrated. Before publishing, check those records and the production Azure configuration; do not blindly merge colliding IDs or overwrite role-bearing users.
