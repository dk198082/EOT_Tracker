# Read-only shared ETO archives — implementation and validation

## Scope and approval boundary

The selected policy keeps production conflicts active and exactly the three
approved workspace number conflicts as read-only archives in one `crm.eto_*`
dataset. Archive visibility and restrictions are implemented but do not install
any live schema. No live DDL, archival/copying, role changes, maintenance or
publishing was performed. Additional split-family scope still requires explicit
review; the planner's dependency blockers remain.

This implements the preparation stage described in
`reports/eto-production-migration-plan.html`. It does not supersede that plan's
snapshot, identity, backup, installation, maintenance or recovery gates.

## Covered behavior

- Active/archive/all discovery, original-number search, source/original ID labels
  and distinct stable links for conflicting versions.
- Readable details, review outputs, comments, history, calculator and file actions.
- No archive detail/output/calculator editing, comments, workflow, splitting,
  file uploads/registration/deletion — including for SuperUsers.
- Server-side enforcement before all request writers and upload URL issuance;
  PostgreSQL triggers protect records and all request-owned tables.
- Database-trusted epoch and stable record identity reject stale/missing/forged
  mutation contexts, including old clients targeting remapped IDs. User/admin
  changes also require the epoch. Browser forms never silently adopt a new identity
  from background queries.
- Assigned-number immutability, active-only uniqueness and an append-only registry
  preventing historical base/split number reuse. Allocation retains the annual
  transaction lock and honors registry high-water values.
- Shared file bytes retained if an archived or active attachment still uses them.
  Signed previews preserve their existing cookie-independent access.
- No archive reminders/OCR updates; legacy role/submitter startup repair is skipped
  after compatible shared activation.
- Legacy schema mode never selects optional columns. Partial/incompatible shared
  schemas fail closed rather than executing DDL or falling back to another dataset.

## Disposable validation

`artifacts/api-server/src/lib/__tests__/shared-archive.integration.test.ts`
generates the full current 18-table schema offline, loads synthetic transformed
production/workspace snapshots and uses the reference staged archive schema.
The local PostgreSQL cluster listens only on an owned Unix socket; it is destroyed
afterward. No source data, Azure credentials, live roles or real file objects are
used. Storage calls are mocked.

Verification covers all-column business-data checksums across the schema addition,
the exact three archived fixture requests, duplicate-number discovery,
every affected write endpoint, stale contexts, simulated roles, shared-blob deletion
and archive downloads, database write/move/delete protection, number retention and
registry allocation, and disabled-guard fail-closed behavior.

The browser pass verified three archive rows, source/original-ID labels, stable
links, archive action hiding, readable history/files and safe empty historical
outputs. It also verified an active comment request's identity headers and a
375-pixel phone layout without page-level overflow. No genuine login or file
destination was exercised. The subsequently added archive calculator visibility
and new-draft upload identity were confirmed with code/type and disposable API
checks; they were not part of the original browser pass.

Browser verification uses a response bank generated by these real routers from
synthetic PostgreSQL data, with every API request intercepted. It can verify
rendering, controls and request headers, but does **not** certify real Entra login,
real object storage, live compatibility, source snapshots or installation readiness.

Repeatable commands:

```sh
pnpm --filter @workspace/api-server exec vitest run \
  src/lib/__tests__/shared-archive.integration.test.ts \
  src/lib/__tests__/shared-identity.ui.test.ts \
  src/lib/__tests__/shared-merge.test.ts \
  src/lib/__tests__/eto-number.test.ts
pnpm run typecheck
pnpm --filter @workspace/api-server run build
```

## Remaining live gates

Real source-specific mapping/recovery validation belongs to the separately scoped
migration work. A live installer must review owner/app permission separation and
prevent app-side DDL, TRUNCATE and registry/marker changes. Both apps and background
writers must be paused and drained before changing IDs or installing the shared
set; reload clients afterward. Execution, live verification and publishing still
require separate approval.
